# 日本語の改行を判断する

「画面に収まった」と「読みやすい」は別の条件。禁則に適合していても、短い助詞・活用語尾だけが次行へ残れば、目立つコピーでは読みにくい。一方、長い本文の単語途中の折り返しを一律禁止すると、行末の余白や横溢れが増える。

## 判定手順

1. 文全体を読み、構文と伝えたいことを把握する。
2. 行末と次行の頭を続けて読み、意味が切れて見える位置を探す。
3. 文字の種類ではなく前後の関係で判断する。`も`という行頭だけで不適切と断定しない。
4. 見出し・リード・短いカード文では意味のまとまりを重視し、本文では通常の日本語組版を基本とする。
5. 助詞だけでなく前の語句を含む最小限のまとまりを次行へ送る候補を比較する。

`｜`は行境界を表す記号。本文に入れない。

| 表示 | 判断と対処 |
| --- | --- |
| `どの関わり方で｜も、あなた自身の目的と意思を尊重します。` | `でも`の途中で分断。重要な短文では`どの関わり方でも、`を候補として保護し、最小幅で収まるか確認する。 |
| `担当した3つの事例｜を、意思決定の中身ごとご確認ください。` | `事例を、`が離れた。`3つの事例を、`等の短い範囲を保護する。余白が過大なら文章幅の調整も比較する。 |
| `Webサイトを、｜営業基盤へ。` | 意味と訴求の区切りが一致する見出し。モバイルでさらに崩れないか確認する。 |
| `サービスを利用できま｜す。` | 語尾だけが目立つ。必要なら`利用できます。`を保護し、収まらないならレイアウトや承認済みコピーを再検討する。 |
| `月額7｜万円` | 数値と単位を合わせる。数値を書き換えない。 |
| `もっと自由に、｜もっと深く。` | 2行目の`も`は助詞の孤立ではない。 |
| `この仕組みは国内｜でも海外でも利用できます。` | 本文では許容できる場合がある。リードでは`国内でも`をまとめる候補を比較する。一律禁止しない。 |

## 避ける対処

- 句点ごとの強制改行、一定文字数による改行。
- 全文の`nowrap`化、すべての文節のブロック化。
- 分割器の結果を最終判断にすること。固有名詞・複合語・数値単位の粒度は用途に合わせて確認する。
- 微小な文字、改行用スペース、ゼロ幅文字、見切れによる隠蔽。
- 指定コピーの無断短縮、デスクトップだけの確認。

見た目の改善とコピーの改善を区別する。元の表現を保つなら短い重要範囲を選択的にまとめる。文の分割や言い換えには意味と承認範囲の照合が必要。どちらも実際の幅・フォントで描画してから判断する。

## 仕様と編集判断

[W3C 日本語組版処理の要件](https://www.w3.org/TR/jlreq/)は行頭・行末禁則や分割禁止の基礎。[CSS Text Level 3](https://www.w3.org/TR/css-text-3/)は自動折り返し・言語指定・CSSの機構。
助詞の孤立、意味のまとまり、短い末行への評価はこのスキルの編集方針。すべてW3Cの禁止事項だと説明しない。
